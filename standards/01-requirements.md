# 01 · 需求 / 活 PRD 〔本项目活记忆 · AI 维护〕

> **作用**:这是本项目唯一的需求文档。所有新功能、缺陷、技术债都追加到这里,不要另起多个 PRD 文件。
> **更新时机**:每次有新需求、需求变更、验收标准变化时更新。

---

## 1. 需求来源

| 类型 | 来源 | 进入方式 |
|---|---|---|
| 功能需求 Feature | 用户 / 老师 / 产品 / 客户 | 写成用户故事 |
| 缺陷 Bug | 测试 / 线上日志 / 用户反馈 | 写复现步骤和期望结果 |
| 技术债 Tech Debt | 开发 / Review / CI/CD 故障 | 写影响和修复目标 |

---

## 2. Issue 生命周期

| 阶段 | 状态 | 动作 |
|---|---|---|
| 提出 | Open | 写清场景、目标、验收标准 |
| 排期 | Backlog / Todo | 决定优先级和负责人 |
| 开发 | In Progress | 从 main 开 feature 分支 |
| 评审 | In Review | 提 PR,等待 CI 和 Review |
| 合并 | Done | PR 合并 main,自动关闭 Issue |
| 验收 | Verified | 按验收标准确认 |

**追踪规则**:分支名带 Issue 号,PR 描述写 `closes #<编号>`。

## 4. 需求清单

### US-1 初始化项目工程结构与 CI · 状态: Backlog

作为 **项目开发者**,
我想要 项目具备基础工程结构、测试框架、CI 流水线,
以便 后续每次开发都能自动检查代码质量,且支持本地 Docker 部署。

验收标准:
- AC1: Given 项目在 feature 分支, When 提交代码, Then PR 触发 CI 流水线,包含 ruff format 检查、ruff lint 检查、pytest 单元测试、Docker 构建。
- AC2: Given CI 流水线执行完成, When 所有检查通过, Then CI 状态为绿色(成功)。
- AC3: Given CI 配置在 `.github/workflows/ci.yml`, When 合并到 main 后, Then 不触发 CD 自动部署(本项目只做 CI)。
- AC4: Given 本地环境安装依赖, When 执行 `docker build`, Then 镜像构建成功。
- AC5: Given 应用通过 Docker 启动, Then 服务监听 8004 端口,健康检查 `/_stcore/health` 返回 200。
- AC6: 完成后更新 `standards/PROGRESS.md`。

技术备注:
- 不做 CD,不涉及服务器部署。CI 仅做质量检查。
- 本地部署方式: `docker run -p 8004:8004 bank-marketing-app`。

### US-2 数据加载与预处理管道 · 状态: Backlog

作为 **数据科学家**,
我想要 可复用的数据加载和预处理函数,
以便 训练和预测阶段使用统一的数据处理逻辑。

验收标准:
- AC1: Given `data/train.csv` 和 `data/test.csv` 存在, When 调用数据加载函数, Then 返回正确的 pandas DataFrame,列数和行数与源文件一致。
- AC2: Given 原始数据, When 调用预处理函数, Then 数值特征进行适当缩放,类别特征进行编码,输出特征矩阵 X 和标签 y。
- AC3: Given 训练集和测试集, When 预处理后, Then 两者的特征列完全一致,无信息泄漏。
- AC4: 预处理函数有单元测试覆盖,覆盖正常输入、缺失值、异常类别值。

技术备注:
- 使用 sklearn Pipeline 封装预处理流程,确保训练/预测一致性。
- 预处理逻辑与训练逻辑分离,便于独立测试。

### US-3 离线模型训练 · 状态: Backlog

作为 **数据科学家**,
我想要 一个可执行的训练脚本,从训练数据中训练分类模型并保存,
以便 后续部署到在线预测系统中使用。

验收标准:
- AC1: Given `data/train.csv`(有标签)和 `data/test.csv`(无标签), When 运行训练脚本, Then 在 train.csv 上训练模型并输出到 `artifacts/model.pkl`。
- AC2: Given 训练好的模型, When 在 train.csv 上用交叉验证评估, Then AUC ≥ 0.85。
- AC3: Given 训练脚本执行完成, Then 打印出关键评估指标(AUC、F1、准确率、混淆矩阵)。
- AC4: Given 相同的随机种子, When 重复运行训练脚本, Then 产出相同的模型(可复现)。

技术备注:
- 训练集无标签,需要用 test.csv 的标签来训练(或将数据合并后划分)。实际方案:合并 train+test,按 8:2 划分训练/验证。
- 模型选择:梯度提升树(如 RandomForest 或 GradientBoosting),适合表格数据,无需 GPU。
- 训练脚本可独立运行: `python src/ml/train.py`。

### US-4 数据分析交互页面 · 状态: Backlog

作为 **银行营销分析师**,
我想要 一个交互式的数据分析页面,可以探索数据分布、特征关系和可视化,
以便 理解数据特征,发现影响认购的关键因素。

验收标准:
- AC1: Given 应用启动, When 用户导航到"数据分析"页面, Then 页面正常渲染,无报错。
- AC2: Given 数据分析页面, When 查看概览, Then 展示数据集基本信息(行数、列数、缺失值统计、数据类型)。
- AC3: Given 数据分析页面, When 选择某个特征, Then 展示该特征的分布图(数值特征用直方图,类别特征用柱状图)。
- AC4: Given 数据分析页面, When 查看相关性分析, Then 展示特征与目标变量(`subscribe`)的相关性热力图或排序列表。
- AC5: Given 数据分析页面, When 选择对比不同群体的认购率, Then 通过筛选器(如下拉框选择职业、婚姻状态等)动态更新认购率图表。
- AC6: Given 数据分析页面, When 查看关键发现, Then 展示 Top N 影响认购的特征及其统计结果。

技术备注:
- 使用 Streamlit 原生组件实现交互(下拉框、滑块、选项卡等)。
- 图表使用 plotly 实现交互式可视化。
- 数据源:优先使用 test.csv(含 `subscribe` 标签)进行分析。

### US-5 在线预测系统 · 状态: Backlog

作为 **银行业务人员**,
我想要 一个通过点选输入客户特征并实时预测是否认购的页面,
以便 快速评估某个客户是否可能认购定期存款产品。

验收标准:
- AC1: Given 应用启动且模型已训练, When 用户导航到"在线预测"页面, Then 页面正常渲染,展示所有输入字段。
- AC2: Given 预测页面, When 所有输入字段通过点选(下拉框、单选按钮等)完成输入, Then 用户点击"预测"按钮。
- AC3: Given 用户点击预测, Then 页面展示预测结果("会认购"/"不会认购")以及预测概率(百分比)。
- AC4: Given 预测结果展示, Then 同时展示影响本次预测的关键特征(如 Top 3 影响因子)。
- AC5: Given 模型文件不存在, When 用户访问预测页面, Then 展示友好提示"请先运行训练脚本"并提供训练命令指引。
- AC6: Given 一组已知结果的测试数据输入, When 进行预测, Then 预测结果与真实标签一致的准确率 reasonable(不要求 100%,但模型 AUC 需 ≥ 0.85)。

技术备注:
- 输入字段与训练特征一一对应,全部使用点选控件(st.selectbox / st.radio),无自由文本输入。
- 预测函数从 `src/ml/predict.py` 调用,加载 `artifacts/model.pkl`。
- 特征重要性可通过模型内置属性(如 feature_importances_)获取。

### US-6 模型训练与预测集成测试 · 状态: Backlog

作为 **项目开发者**,
我想要 端到端测试验证"训练 → 保存模型 → 加载模型 → 预测"全链路,
以便 确保离线训练与在线预测的一致性。

验收标准:
- AC1: Given 训练脚本执行完成, When 调用预测函数对同一条数据预测, Then 返回 "yes" 或 "no" 且预测概率在 [0, 1] 范围内。
- AC2: Given 预测函数, When 输入多条数据批量预测, Then 返回结果数量与输入一致。
- AC3: Given 同一模型文件, When 多次加载并预测同一条数据, Then 结果完全一致(确定性)。
- AC4: Given 预测函数, When 输入包含未知类别值, Then 优雅处理(不崩溃,给出合理预测或提示)。

## 5. 非功能需求

- **安全**:密钥只进 Secrets,不进 Git;数据集不进 Git。
- **可维护**:一需求一小 PR,避免大爆炸式提交。
- **可测试**:核心逻辑(预处理、预测)必须有单元测试,覆盖率 ≥ 80%。
- **可部署**:Docker 构建成功,本地 `docker run -p 8004:8004` 可启动,健康检查通过。
- **性能**:预测响应时间 < 2 秒(本地部署,非生产级要求)。
- **可复现**:训练脚本固定随机种子,相同输入产出相同模型。
